# ui2c

**Переносимая неблокирующая библиотека I²C controller для встраиваемых систем без обязательного использования RTOS.**

[English version](README.md)
[Руководство по портированию](PORTING_RU.md)

> **Статус:** предварительная версия. Переносимое ядро и API v1 реализованы. Backend для STM32F051 создан в исходном firmware-проекте, но полная аппаратная проверка ещё не завершена. Поддержка остальных микроконтроллеров пока не заявляется.

## Какую задачу решает ui2c?

Производители микроконтроллеров предлагают несовместимые периферийные интерфейсы, механизмы прерываний, DMA и способы выполнения I²C-транзакций. При этом драйверы внешних устройств не должны зависеть от особенностей конкретной периферии.

`ui2c` предоставляет компактный единый интерфейс транзакций. Платформозависимый backend исполняет их средствами конкретного микроконтроллера. При переносе приложения между MCU можно сохранить код драйверов устройств, заменив порт и BSP.

## Основные принципы

- **Независимое ядро.** В core отсутствуют зависимости от CMSIS, HAL, RTOS и конкретной платы.
- **Единый API транзакций.** Приложение задаёт последовательность сообщений, а не операции с регистрами периферии.
- **Неблокирующая работа.** Отправка запроса не ожидает завершения обмена; callback вызывается через `ui2c_process()`.
- **Управление аппаратурой в порте.** IRQ, DMA, polling, START/RESTART/STOP и errata конкретного MCU относятся к backend.
- **Явные возможности.** Неподдерживаемые сочетания сообщений отклоняются, а не заменяются другими последовательностями на шине.
- **Без динамического выделения памяти и скрытого планировщика.** Core не содержит heap, очередь запросов и автоматические повторы.
- **Разделение ошибок и политики.** Потеря арбитража, NACK, занятость шины, отмена и timeout возвращаются клиенту. Решение о повторе принимает приложение.
- **Независимость от платы.** Pinmux, тактирование, выбор DMA/IRQ и параметры шины задаются в BSP.

## Архитектура

```text
Приложение / драйвер устройства    запросы, retry/backoff
                |
             ui2c.h               публичный API
                |
             ui2c.c               валидация, состояния, timeout, callback
                |
           ui2c_port.h            контракт backend
                |
       Порт микроконтроллера       аппаратный автомат, IRQ/DMA/polling
                |
               BSP                выводы, тактирование, привязка периферии
```

Самостоятельный репозиторий `ui2c` включает **core и контракт backend**. Аппаратные порты могут находиться в firmware-проектах либо в собственных репозиториях. Их **не требуется хранить внутри Git submodule** с ядром. Код BSP конкретной платы также не входит в core.

## Пример использования

```c
#include "ui2c.h"

static uint8_t chip_id_register = 0xD0;
static uint8_t chip_id;

/* Дескрипторы и буферы должны существовать до вызова callback. */
static const ui2c_msg_t messages[] = {
    { .data.tx = &chip_id_register, .len = 1, .flags = UI2C_MSG_WRITE },
    { .data.rx = &chip_id, .len = 1, .flags = UI2C_MSG_READ | UI2C_MSG_RESTART },
};

static void on_complete(ui2c_t* bus, ui2c_status_t status, void* arg) {
    (void)bus;
    (void)arg;
    if (status == UI2C_STATUS_OK) {
        /* chip_id содержит прочитанное значение. */
    }
}

ui2c_status_t read_chip_id(ui2c_t* bus) {
    const ui2c_addr_t address = {
        .value = 0x76,       /* 7-битный адрес без сдвига. */
        .mode = UI2C_ADDR_7BIT,
    };
    return ui2c_xfer(bus, address, messages, 2, on_complete, NULL);
}

/* В основном цикле регулярно вызывается ui2c_process(bus). */
```

`UI2C_STATUS_OK` от `ui2c_xfer()` означает **принятие запроса**, но не завершение обмена. Callback доставляется из `ui2c_process()` вне контекста прерывания.

## Контракт исполнения

- Публичный API вызывается из одного сериализованного foreground-контекста. Вызовы из ISR или нескольких конкурентных задач контрактом core не разрешены.
- Для одной шины допускается один запрос, включая запрос с готовым результатом, который ожидает callback.
- Дескрипторы, TX/RX-буферы и контекст callback должны сохраняться до завершения запроса.
- Backend владеет работой с аппаратурой и прекращает доступ IRQ/DMA к памяти запроса до завершения или отмены.
- Интеграция предоставляет монотонное время в миллисекундах; для обнаружения timeout необходимо регулярно вызывать `ui2c_process()`.
- `ui2c_cancel()` останавливает локальную периферию, но не гарантирует физическое освобождение внешних линий I²C.
- Core не выполняет автоматическое восстановление линий, повторы после потери арбитража и синхронизацию нескольких мастеров по временны́м слотам.

## Подключение

Переносимое ядро подключается через CMake:

```cmake
add_subdirectory(components/ui2c)
target_link_libraries(your_target PRIVATE ui2c::core)
```

Независимый порт конкретного MCU линкуется с core и предоставляет реализацию аппаратных операций, инициализацию и обработку IRQ. BSP конфигурирует периферию и создаёт экземпляр шины.

## Ограничения и дальнейшее развитие

Текущая реализация ориентирована на режим I²C controller. Режим target/slave, автоматические повторы, очереди запросов, SMBus и универсальный bus recovery не входят в действующий контракт core. Поддержка новых MCU будет объявляться только после реализации и проверки соответствующих backend.
