# Индикация ГРИ

`app_display` хранит профиль платы, отображает время из `app_clock` и разрешает
индикацию при готовности HV. Текущая плата показывает **ЧЧ:ММ:СС**, 24 часа,
с ведущим нулём. Все четыре внешние точки синхронно горят в чётные секунды RTC
и погашены в нечётные: одна секунда включены, следующая выключены.

Пока время не установлено, дисплей погашен. Установить дату и время можно через CLI:

```text
clock set -d 2026-11-02 -t 12:34:56
clock
```

Отображается время, записанное в RTC, без преобразования часового пояса.
`clock invalidate` гасит индикацию до следующей установки времени.

## Профиль платы

Редактируемый профиль — `src/display_profile.c`.

- `in12_cathode_channels[]` сопоставляет локальные электроды каналам **CATHODE_0..15**.
  Порядок: цифры **0..9**, затем запятая ИН-12Б. Это не номера физических выводов лампы.
  Для разных разводок сокетов задайте отдельные таблицы.
- В `upper_board[]` каждому элементу задаются тип лампы, **ANODE_0..7** и таблица катодов.
  ИН-12А использует первые десять записей; ИН-12Б — все одиннадцать.
- Элементы **0..5** — цифровые лампы слева направо. **6/7** — левая пара внешних точек,
  **8/9** — правая. Их катоды: **3/13** и **7/10**, общий анод — **A2**.
  У каждой точки свой токоограничивающий резистор; выбранные точки могут светиться вместе.
- `brightness_pm` задаёт общую яркость, `anode_brightness_pm[ANODE_n]` — коэффициент анода.
  Диапазон обоих — **0..1000**. Запись `[2]` управляет яркостью всех точек на A2.
- `timing` содержит частоту полного обновления и межразрядную паузу гашения.
  Текущие значения: **240 Гц / 500 мкс**.
- `clock_roles[]` задаёт назначение каждого элемента в том же порядке, что `upper_board[]`:
  десятки/единицы часов, минут, секунд или внешняя точка. Для четырёх ламп оставьте
  роли часов и минут и нужные точки; порядок элементов может быть произвольным.
  `APP_DISPLAY_CLOCK_UNUSED` оставляет элемент погашенным. Длина таблицы должна
  равняться числу элементов платы; текущий профиль проверяет это через `_Static_assert`.
  `.clock_roles = NULL` отключает автоматическое отображение времени и оставляет
  ручную передачу кадров. Роли и необходимые для них символы проверяются при выборе профиля.

При другом подключении точек можно задать общий анод на пару либо отдельный на точку.
Элементы одного анода должны иметь непересекающиеся катодные каналы и независимое
ограничение тока. Точки с одинаковыми анодом и катодом описываются одним элементом.
`NIXIE_CHANNEL_FIXED` допустим для однокатодного элемента с постоянным возвратом
и требует отдельного анода. Если точек нет, удалите их строки из `upper_board[]`
и соответствующие записи `clock_roles[]`.

Необязательные поля `anode_pin` / `cathode_pins` описывают физические выводы лампы.
Ноль / NULL означает «не указано»; разводка определяется только логическими каналами.

## Передача кадра

При `.clock_roles = NULL` кадрами полностью управляет вызывающее приложение.
Если роли заданы, `app_display_process()` поддерживает кадр часов и заменяет
вручную переданные символы при следующем опросе.

`app_display_present()` принимает один ID символа на каждый элемент платы.
Массив копируется во время вызова; его длина должна равняться `board.element_count`.
Для текущих десяти элементов:

```c
const uint8_t symbols[] = {
    1U, 2U, 3U, 4U, 5U, 6U,
    NIXIE_SYMBOL_ON, NIXIE_SYMBOL_BLANK,
    NIXIE_SYMBOL_ON, NIXIE_SYMBOL_BLANK,
};
nixie_status_t result = app_display_present(symbols, sizeof(symbols) / sizeof(symbols[0]));
```

Цифры имеют ID **0..9**, запятая ИН-12Б — `NIXIE_SYMBOL_DOT`, внешняя точка —
`NIXIE_SYMBOL_ON`. `NIXIE_SYMBOL_BLANK` гасит элемент. Запятая выбирается вместо цифры.
Другие типы ламп добавляются описателями символов и разводки.

`NIXIE_OK` означает, что кадр принят. При `NIXIE_BUSY` один кадр уже ожидает применения:
вызывающее приложение должно повторить передачу позднее. Ошибки возвращаются вызывающему
приложению; предыдущие символы и настройки сохраняются. Все вызовы выполняются из foreground.

`app_display_configure()` выбирает профиль и гасит все его элементы.
`app_display_set_parameters()` обновляет яркость, refresh rate и blanking time вместе,
сохраняя текущие символы и коэффициенты яркости анодов. Описатели и таблицы выбранной
платы и массив ролей должны оставаться действительными и неизменными в памяти.

Опрос RTC выполняется из основного цикла не чаще одного раза за тик 1 мс.
Кадр компилируется и передаётся только при изменении символов. При `NIXIE_BUSY`
принятые символы не меняются: следующий опрос повторяет отправку актуального времени.
Невалидный календарь или неготовые RTC/LSE формируют погашенный кадр;
неудавшееся чтение согласованного снимка RTC сохраняет предыдущий кадр до повторного чтения.
Настройки яркости и таймингов из `display set` сохраняются при смене времени.

Обновление содержимого зависит от обслуживания основного цикла. Блокирующие операции
BME280 и длинный вывод CLI могут задержать смену секунды и мигание точек.
Развёртка TIM1 продолжает показывать последний принятый кадр из IRQ.

## Сканирование

`components/nixie` проверяет входные данные и компилирует MCU-независимый план.
Один используемый анод получает один слот; катоды выбранных элементов этого анода
объединяются в общую маску. Яркость регулируется ШИМ анода.

Текущая плата имеет **7 слотов**: **A0 → A1 → A3 → A4 → A5 → A6 → A2**.
Порядок определяется первым появлением анода в `upper_board[]`. Погашенный анод
сохраняет слот, поэтому изменение символов не меняет коэффициент мультиплексирования.

Пределы компонента — 16 элементов, 16 анодов и 16 катодов. BSP текущего carrier
поддерживает 8 анодов и 16 катодов. GPIO по `.ioc` определены в `bsp/src/bsp_pins.h`;
аноды и катоды активны HIGH. Незаданные каналы, повторы электродов и неуправляемое
совместное включение отклоняются до публикации. Диагностика указывает индекс элемента;
255 означает ошибку всей конфигурации.

## CLI

```text
display
display set --brightness 50 --refresh-rate 240 --blanking-time 500
display set -b 50 -r 240 -t 500
display set --help
```

- `-b` / `--brightness`: общая яркость, целое число **0..100%**; 0 гасит все элементы.
- `-r` / `--refresh-rate`: число полных проходов в секунду, **1..400 Гц**.
- `-t` / `--blanking-time`: межразрядная пауза гашения, **0..65535 мкс**; 0 отключает паузу.

Параметры можно менять в любом сочетании. Они проверяются и публикуются вместе;
ошибки аргументов, повторные опции и недопустимые сочетания оставляют настройки прежними.
Настройки хранятся в RAM; после reset используются значения профиля.

`display` показывает состояние сканирования и принятые настройки, которые могут ожидать
границы кадра. `Missed slots` — накопленный с запуска счётчик пропусков включения и
выключений ШИМ, опоздавших до следующего update. При оценке новых параметров смотрите
его прирост: смена настроек счётчик не обнуляет.

## TIM1 и публикация

BSP использует TIM1 с шагом **1 мкс**, update и CC1/CC2 IRQ с приоритетом **2**.
Update выключает все аноды и сразу фиксирует `off_time = TIM1->CNT` в коротком
участке с запрещёнными IRQ. Включение назначается на `off_time + blanking_time_us`;
служебная обработка выполняется внутри паузы. CC1 задаёт катоды и включает анод,
CC2 выключает его по окончании импульса. При 100% анод выключается следующим update.

```text
Tslot      = round(1 000 000 / (refresh_rate_hz * slot_count))
Ton_budget = Tslot - blanking_time_us
brightness = round(global_brightness * anode_brightness / 1000)
Ton        = round(Ton_budget * brightness / 1000)
```

Период должен помещаться в таймер, а blanking time — быть строго меньше слота.
Импульс, округлённый до нуля, остаётся погашенным. Отдельного минимального импульса нет.
При **240 Гц / 500 мкс** слот равен **595 мкс**, расчётный максимум свечения — **95 мкс**.
При 590 мкс остаётся 5 мкс: задержки IRQ могут привести к пропуску даже при допустимых
числовых параметрах. Передача кадра не подтверждает достижимость его тайминга на GPIO.

Два статических аппаратных буфера содержат готовые операции GPIO и адреса анодов.
Новый план применяется на границе полного прохода после гашения анодов.
При смене периода счётчик перезапускается только на этой границе; первый слот
отсчитывается от нуля нового периода. Обработчик CC1 не выполняет поиск пинов.
Публичный приём плана BSP отдельно проверяет его границы и маски перед копированием.

## HV и остановка

`app_main` впервые разрешает индикацию после `APP_HV_RUNNING`, сохраняя разрешение
при обычном возврате регулятора в `APP_HV_STARTING`. OFF/FAULT отзывают его в основном
цикле. Пока разрешения нет, приложение может принимать кадры и параметры.
`app_display_process()` обслуживает это разрешение и формирует кадр часов по профилю.

`bsp_nixie_set_enabled(false)` останавливает таймер и гасит выходы.
Error_Handler/HardFault/NMI вызывают защёлкиваемый `bsp_nixie_shutdown()`;
повторный запуск после него возможен только после reset.
