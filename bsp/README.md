# FlashDB KVDB на STM32F051

Приложение использует API FlashDB напрямую. BSP содержит аппаратный FAL-порт,
конфигурацию и экземпляр базы. Сборка библиотеки описана в
`bsp/cmake/flashdb.cmake`, подключаемом из `bsp/CMakeLists.txt`.
Исходники FlashDB и поставляемого с ним FAL не изменены и закреплены submodule
`components/FlashDB` на commit `db0afd9` (версия в заголовке 2.2.99).
Лицензии upstream сохранены в submodule.

## Консоль

После обычного входа в shell:

```text
kv info
kv set -k device.name -v "Desk clock"
kv get -k device.name
kv list
kv del -k device.name
kv --help
kv set --help
```

Ключ: 1–31 ASCII-символ (`A-Z`, `a-z`, `0-9`, `.`, `_`, `-`). Значение:
до 128 байт текста; пробелы заключаются в двойные кавычки. FlashDB сохраняет
строки без завершающего NUL. Shell не передаёт пустой аргумент `""`; пустые blobs
доступны через API FlashDB. Строка консоли увеличена до 256 байт.

`set`/`del` требуют WRITE или ADMIN, чтение — READ или ADMIN. Неизвестные,
повторные и лишние параметры, слишком длинные ключи/значения отклоняются до
изменения базы. Повторный `set` идентичного значения не пишет Flash. Прямые
вызовы FlashDB такой оптимизации не получают.

`get` также показывает binary blobs приложения: управляющие байты выводятся
как `\xNN`, вывод ограничен 129 байтами с явным сообщением об усечении.
`info` показывает сумму размеров живых записей, **не** свободную ёмкость:
место также занято заголовками секторов, старыми записями и резервом для GC.

## Память и контракт

- Код: `0x08000000..0x0800F7FF` (62 КиБ).
- База `settings`: `0x0800F800..0x0800FFFF` (2 КиБ, две страницы по 1 КиБ).
- Linker region SETTINGS не содержит загружаемых секций. Код не может занять
  раздел базы; BSP дополнительно проверяет linker symbols при инициализации.
- FAL-устройство открывает только этот раздел, а не всю Flash MCU. Проверяются
  границы, выравнивание, HAL-результаты, чтение после записи и стирания.
- Гранулярность FlashDB — 32 бита, физически две записи по 16 бит. Их нельзя
  считать атомарной 32-битной операцией. Неизменившиеся halfwords пропускаются;
  программирование других нестертых halfwords запрещено.
- KVDB без TSDB, без KV/sector caches; статический экземпляр, без heap.
- Все вызовы выполняются последовательно из foreground. Из ISR и конкурентных
  задач вызывать нельзя. Для RTOS нужно отдельно настроить lock/unlock.
- Запись и GC блокируют основной цикл. На single-bank F051 также задерживается
  выборка инструкций из Flash: это может влиять на UART/I2C, таймауты и watchdog.
  `HAL_FLASH_Program_IT` само по себе не устраняет остановку выборки инструкций.
- Гарантия нескольких согласованных параметров требует одного сериализованного
  blob; несколько `set` не являются транзакцией.

Инициализация вызывается после запуска консоли; при возвращённой ошибке консоль
остаётся доступной. Используется штатное восстановление FlashDB, включая
автоформатирование секторов с невалидным заголовком. Чистый раздел автоматически
инициализируется при первом запуске. **Это не режим сохранения любых повреждённых
данных:** при невалидных заголовках upstream может потерять содержимое сектора.
Не добавлен автоматический сброс всей базы при любой ошибке приложения.

Обычная прошивка ELF через существующий target `flash` не содержит данных в
SETTINGS. Target `erase` стирает весь чип, включая настройки. После CubeMX
регенерации необходимо сохранить разметку и symbols в linker script. При первом
переходе со старой прошивки убедиться, что последние 2 КиБ освобождены от её кода.

При первоначальной интеграции FlashDB прежняя Debug-сборка не помещалась в 60 КиБ.
После уменьшения базы коду доступно 62 КиБ. Debug использует
`-Og -g3`; Release сохраняет `-Os`/LTO.

## API приложения

```c
#include "bsp_storage.h"

fdb_kvdb_t db = bsp_storage_db();
if (db != NULL) {
    fdb_err_t result = fdb_kv_set(db, "device.name", "Desk clock");
    /* Проверить result; FDB_SAVED_FULL означает нехватку места. */
}
```

Для бинарных данных — `fdb_kv_set_blob`, `fdb_kv_get_blob`, `fdb_blob_make`.
Наличие ключа можно проверить `fdb_kv_get_obj`; нулевая длина результата blob
сама по себе не отличает отсутствующий ключ от пустого значения.
Версию и сериализацию прикладных структур определяет приложение.

Перенос: адаптировать `bsp/cmake/flashdb.cmake` и конфигурацию
`bsp/include/fdb_cfg.h`/`bsp/include/fal_cfg.h`, реализовать FAL
device callbacks, выделить защищённый раздел. Target `flashdb` сохранён.
Зависимостей от STM32 у библиотеки
нет; STM32 HAL используется только в `bsp/src/bsp_flash_fal.c`.

## Известное ограничение

При моделировании частично запрограммированного halfword в прежней конфигурации
4 КиБ наблюдалась потеря обновляемого ключа при восстановлении на переходе к GC.
Частично записанное поле статуса нельзя безопасно допрограммировать текущим
F051-портом; upstream recovery не сохраняет ключ в этом сценарии.
Уменьшение раздела до 2 КиБ не устраняет причину; новая конфигурация не проверена.
Полная устойчивость к внезапному отключению питания не подтверждена.

Тестовая инфраструктура проекта удалена по решению пользователя. Не добавлять
тесты и не запускать тесты или сборку без явного запроса пользователя.
