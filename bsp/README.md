# BSP STM32F051x8: CMSIS без HAL/LL

Архитектурная граница зафиксирована в [описании проекта](../README.md#архитектура-проекта).
`platform/src` содержит main, системную поддержку MCU, libc hooks и входы IRQ.
В текущем CMSIS-варианте `bsp/src` владеет ручной подготовкой периферии платы,
её рабочими операциями и ошибками. BSP напрямую использует регистры и
определения CMSIS Device ST. HAL/LL и промежуточный API периферии не подключены.

`platform` и `cmake/platform/CMakeLists.txt` поддерживаются вручную.
Target `platform` передаёт device headers и определения MCU, подключает
системные исходники и startup. Main вызывает BSP после системного тактирования;
файл векторов направляет IRQ соответствующим BSP-обработчикам. При переходе на
генерируемую HAL/LL-конфигурацию файлы генератора размещаются в platform.

## Подготовка платы

`bsp_board_init()` — единственная точка начальной подготовки текущей платы.
Вызывается один раз после `SystemClock_Config()`, с работающим SysTick,
до `app_main()`. Порядок прежней инициализации сохранён:

1. `bsp_board.c`: общие GPIO и DMA clock/NVIC.
2. `bsp_rtc_hw_init()`: календарь и его синхронизация в `bsp_rtc.c`.
3. `bsp_console_hw_init()`: USART1 и его выводы в `bsp_console.c`.
4. `bsp_i2c_hw_init()`: I2C1, выводы и исходная конфигурация DMA в `bsp_i2c.c`.
5. `bsp_buzzer_hw_init()`: TIM16 и PA6 в `bsp_buzzer.c`.
6. `bsp_ws2812_hw_init()`: TIM2 и исходная конфигурация DMA1 CH1 в `bsp_ws2812.c`.
7. `bsp_hv_hw_init()`: ADC, TIM3 и TIM17/PA7 в `bsp_hv.c`, в этом порядке.
8. `bsp_nixie_hw_init()`: TIM1, остановленный до публикации корректного плана,
   и EXTI13 по обоим фронтам PC13 для независимых разделителей.

После подготовки приложение запускает рабочие BSP-драйверы на прежних местах.
TIM3 остаётся остановленным до готовности ADC; TIM17 получает HIGH idle,
CCR1=0 и MOE=0 до подключения PA7 к AF. Ошибки начальной синхронизации RTC
или готовности UART вызывают `Error_Handler()` с отключением HV. Остальные
проверки рабочих `*_init()`, обработка отказов и восстановление сохранены.

`bsp/src/bsp_hw.h` — частный заголовок CMSIS-конфигурации этой платы:
он связывает BSP-модули при старте и содержит общие расчёты регистров таймеров.
Публичные интерфейсы устройств не открывают эти точки подготовки приложению.

Прикладные API, приложения, команды, stdio/CRLF, библиотеки и регистровый
backend ui2c сохранены. Добавлены только BSP-точки входа для dispatch IRQ.
FlashDB не возвращается; Flash — 64 КиБ, RAM — 8 КиБ, без раздела SETTINGS.
Наличие исходников FlashDB в submodule не означает включение в сборку.

## Общие аппаратные параметры и расчёты таймеров

Определения разделены по назначению:

- `bsp/include/bsp_board_config.h` содержит только требования устройств:
  частоты buzzer, HV PWM, выборки HV ADC и параметры кодирования WS2812.
- `platform/include/platform_config.h` содержит настройку тактирования MCU: HSI,
  PLL и производную HCLK. PLL задаётся через `RCC_CFGR_PLLMUL12` из CMSIS;
  это же значение используется при настройке RCC и вычислении HCLK.
- `bsp/src/bsp_hw.h` содержит производные значения регистров конкретных
  TIM2/TIM3/TIM16/TIM17. Подготовка платы и проверки BSP используют
  одни и те же расчёты. AHB и APB сохраняют делители 1.

Публичные заголовки BSP не подключают заголовки platform или регистры STM32.
Порядок настройки периферии и рабочие частоты сохранены. Общие GPIO
согласованы с распиновкой и параметрами актуального `.ioc`.
Числовые маски и позиции полей GPIO/AF/EXTI/RTC заменены определениями CMSIS;
параметры платы и значения без соответствующих макросов ST остаются числовыми.

`platform/include/timer_calc.h` содержит независимые арифметические макросы
`TIMER_CALC_PSC`, `TIMER_CALC_ARR`, `TIMER_CALC_RATE_HZ`: округление делителя
PSC к ближайшему целому, усечение периода ARR и вычисление частоты из
полученных PSC/ARR. Подход соответствует прежним калькуляторам ST, но не
требует HAL/LL. Аргументы должны соответствовать описанным предусловиям;
промежуточные результаты расширены до uint64_t, чтобы проверять диапазон
до сужения к регистру. В текущей конфигурации все аргументы — константы.

`BSP_HV_SAMPLE_RATE_HZ` в публичном BSP API берётся из задания BSP для ADC.
Проверка в `bsp_board.c` подтверждает, что рассчитанный период TIM3 даёт ровно эту частоту.
Приложение использует его для Ki, частоты управления, времени стабилизации
и счётчика startup timeout. Это настроенная частота TRGO, не измерение
фактического потока ADC. Параметры PI/фильтра остаются в приложении.

`_Static_assert` проверяют точную делимость частот, диапазоны PSC/ARR,
середину DMA-слота WS2812, длину DMA-буфера и ширину счётчиков приложения.
Недостижимая либо не помещающаяся конфигурация отклоняется при компиляции.
Номинальные значения в таблице ниже сохранены; `.ioc` остаётся справочным
представлением и при изменении настроек актуализируется вручную.

## Аппаратный контракт

| Узел | Конфигурация |
| --- | --- |
| CPU / AHB / APB | HSI / 2 × 12 = 48 МГц, делители шин 1, Flash 1 wait state |
| Время | SysTick 1 мс, `bsp_time_ms()` с переполнением `uint32_t` |
| USART1 | PA9/PA10 AF1, PCLK, 1500000 8N1, oversampling ×16, TX DMA1 CH4, RX CH5 |
| I2C1 | PB6/PB7 AF1 open-drain, HSI 8 МГц, TIMINGR 0x00201D2B, TX CH2, RX CH3 |
| Buzzer | PA6 AF5, TIM16 PWM1, PSC=47, ARR/CCR1 с preload |
| WS2812 | PD2 open-drain, TIM2 CC3 → DMA1 CH1 → GPIOD BSRR, PSC=0, ARR=19, CCR3=10 |
| HV PWM | PA7 AF5, TIM17 PWM1, инвертированная полярность, PSC=0, ARR=1599 (30 кГц по умолчанию) |
| HV ADC | PA2 / IN2, HSI14 14 МГц, 12 бит, sampling 239.5 cycles, TIM3 TRGO 2 кГц |
| RTC | LSE, prescaler 127/255, 24 часа, калибровочный выход PC13 1 Гц |
| Кнопки | PC0..PC3 pull-up, EXTI по обоим фронтам |
| Индикация ГРИ | TIM1 1 МГц, update + CC1/CC2 IRQ priority 2, GPIO BSRR; один слот и ШИМ на анод, маска катодов, blanking time для TLP127, без DMA |
| Разделители ИНС-1 | Постоянные GPIO: A2, катоды 3/13 слева и 7/10 справа; PC13 LOW разрешает свечение, EXTI13 priority 3 по обоим фронтам |
| Аноды | ANODE_0..7: PB11, PB10, PB2, PB1, PB0, PC5, PC4, PA5 |
| Катоды | CATHODE_0..15: PB9, PB8, PB5, PB4, PB3, PC12, PC11, PC10, PC9, PC8, PC7, PC6, PB15, PB14, PB13, PB12 |

Все 8 анодов и 16 катодов настраиваются по `.ioc`: push-pull, HIGH speed,
без подтяжек, начальный LOW. Защёлки всех этих выходов сбрасываются через BSRR
до переключения MODER; OTYPER, OSPEEDR и PUPDR также задаются до включения выхода.
PA5 и катодные выводы исключены из списка analog. Неиспользуемые PA0/PA1/PA3/PA4/
PA8/PA11/PA12/PA15 и PF0/PF1/PF4/PF5/PF6/PF7 остаются analog без подтяжек.
PD2 сохраняет open-drain, HIGH speed, no-pull и начальный LOW.
SWD PA13/PA14, RTC PC13 и LSE PC14/PC15 общая настройка GPIO не затрагивает;
RTC/LSE подготавливаются своими регистрами, AF периферии — в соответствующих `*_hw_init()`.
`bsp_rtc_hw_init()` оставляет цифровой вход PC13 включённым без подтяжек для
чтения фактической фазы RTC_CALIB. Выходом продолжает управлять RTC.
PA7 устанавливается в HIGH до подключения альтернативной функции TIM17.

Названия выводов по `.ioc` централизованы в частном `bsp/src/bsp_pins.h`.
Настройка GPIO и backend индикации используют одну привязку анодов/катодов.
Профиль верхней платы и передача кадров описаны в [app_display](../apps/app_display/README.md).

NVIC: UART, I2C и DMA — priority 0, ADC — 1, индикация TIM1 — 2, EXTI и SysTick — 3.
UART и его DMA имеют одинаковый приоритет, поэтому их обработчики не прерывают
друг друга при работе с общим состоянием консоли. Каналы DMA закреплены за
периферией; совместное использование канала другими модулями не поддерживается.

## Консоль

Контракт `bsp_console_write()` сохранён: один foreground-производитель,
прерывания и SysTick включены; вызов из ISR или с PRIMASK=1 отклоняется.
TX ring — 64 байта (63 полезных), RX ring — 64 байта, RX DMA — 16 байт.
Длинная запись порционно заполняет TX ring и возвращается после USART TC,
когда завершилась передача последнего stop bit. DMA TC лишь переключает
ожидание на USART TC. Таймаут 100 мс ограничивает отсутствие прогресса,
а не общую длительность длинного сообщения. Форматирование и CRLF не менялись.

При TX DMA TE сначала останавливается канал, затем читается CNDTR. Переданный
в USART префикс завершается через TC, оставшийся суффикс повторяется из
foreground. При таймауте TX запрос DMA и IRQ TC выключаются, канал
останавливается, очередь сбрасывается и возвращается -1. Уже переданный
префикс отозвать невозможно; повтор всего сообщения может дать дубликаты.
Возврат успеха не подтверждает получение байтов терминалом.

Circular RX обслуживается по HT/TC/IDLE с общим курсором и учётом TC.
HT включён, чтобы обслуживать непрерывный поток до полного оборота DMA.
UART/DMA ошибка останавливает RX; перезапуск выполняется из process(),
в том числе во время блокирующей записи. В интервале перезапуска данные
теряются. При заполнении RX ring очередной блок отбрасывается. Более одного
необслуженного оборота DMA восстановить невозможно; задержки IRQ должны
оставаться меньше длительности оборота 16 байт: 160 мкс при 1000000 baud, 8N1.

## WS2812 и I2C

WS2812 сохраняет API, копию кадра, максимум 12 LED, буфер 2 × 72 слова,
счётчики ошибок, проверку фазы CNDTR до и после refill, таймаут передачи 5 мс
и latch 2 мс. DMA TE, одновременно ожидающие HT/TC либо неверная фаза
прерывают передачу с соответствующей диагностикой. Канал останавливается,
PD2 принудительно переводится в LOW, затем выдерживается latch.
Уже переданный повреждённый кадр восстановить невозможно. Время refill
и фактическая форма импульсов требуют проверки на плате.

I2C сохраняет ui2c, таймаут 100 мс, DMA threshold 16 и повтор инициализации
раз в секунду. BSP настраивает clocks/GPIO/DMA/NVIC, ui2c владеет состоянием
передачи и IRQ. Протокол и обработка ошибок ui2c не изменены.

## HV

ШИМ HV при запуске работает на 20 кГц (48 МГц / 2400); начальная настройка
TIM17 и проверка BSP используют общий расчёт. В справочном `.ioc` пока задан
ARR=1599 (30 кГц), это известное расхождение с прошивкой. ADC выдаёт 2000 отсчётов/с;
регулятор выполняется на каждом втором отсчёте, то есть на 1 кГц вместо 100 Гц.
IIR-фильтр имеет коэффициент 1/4 вместо 1/16: постоянная времени около
1,74 мс вместо 7,75 мс. Это уменьшает задержку ценой меньшего подавления помех.

Частота PWM меняется во время работы через `hv set -f <20000..50000>`
или `hv set --frequency <20000..50000>`; единица — Гц. Можно одновременно
задать напряжение: `hv set -v 180 -f 30000`. Все аргументы проверяются
до изменения параметров; повтор одной опции отклоняется. В `hv` и `hv -w`
частота PWM показана отдельно от частоты отсчётов ADC. Отображается частота,
рассчитанная из периода TIM17 и округлённая до целого Гц; это не измерение.
Период округляется до ближайшего целого числа тактов, поэтому произвольная
заданная частота может быть представлена приближённо.

`bsp_hv_set_frequency()` вызывается из foreground. На время записи ARR/CCR1
маскируются IRQ и устанавливается UDIS, чтобы preload-регистры обновились
согласованно на следующей границе периода. CNT не сбрасывается, MOE
не меняется, Duty пересчитывается для нового периода с округлением до такта.
Состояние PI, уставка, запрос включения и временная OVP-блокировка сохраняются.
Команда доступна также в OFF/FAULT и не включает выход. Частота сохраняется
при автоповторе, но после reset возвращается к 20 кГц; записи во Flash нет.
Частоты ADC/регулятора и коэффициенты PI при этом не меняются.
20..50 кГц — экспериментальный диапазон, а не подтверждение работоспособности
силовой части при любой нагрузке; смена частоты может менять переходный процесс.

Soft start удалён: уставка применяется полностью с первого шага, без ramp
напряжения и без ограничения скорости роста duty. Выход рассчитывается
позиционным PI: `u = Kp * error + integral`, с отдельным интегратором в Q16
промилле. Ошибка выражена в 0,1 В; Kp = 2,5 промилле/В,
Ki ≈ 4,88 промилле/(В·с) при периоде 1 мс. Пропорциональное усиление сохранено,
интегральное усиление в секунду уменьшено в 6,4 раза. Интегратор ограничен
диапазоном 0..duty limit; накопление блокируется, если ошибка усиливает
насыщение выхода. Односторонний slew limiter больше не искажает P-составляющую.
При смене уставки интеграл сохраняется: отрицательная ошибка немедленно
уменьшает P-составляющую и постепенно снижает I. Это убирает искусственный
повторный разгон с нулевого интеграла при снижении уставки; скорость снижения
выхода по-прежнему зависит от нагрузки. При выключении или fault интеграл обнуляется.

`STARTING` означает ожидание стабилизации, без замедления управления:
`RUNNING` выставляется после 50 мс непрерывно в полосе ±3 В. При выходе
из полосы статус возвращается в `STARTING`, без сброса интегратора или PWM.
На повторное достижение полосы также нужны 50 мс. Таймаут достижения/восстановления
регулирования — 20 с (20000 шагов по 1 мс); `NO_REGULATION` проверяет
недобор более 10 В. При потере `RUNNING` отсчёт этих 20 с начинается заново.
Duty limit — 98%, порог OVP — 260 В, таймаут ADC — 10 мс.
Начальная уставка — 180 В, допустимый диапазон — 100..250 В. После успешного
init запрос работы включён по умолчанию: первый вызов `app_hv_process()`
с полученным отсчётом ADC запускает преобразователь. После `NO_REGULATION`,
OVP или timeout ADC выполняются повторные попытки с паузой 1000 мс после
аварии и между неудачными попытками. Ожидания разряда до 30 В нет.
`hv off` выключает PWM и отменяет запрос работы, включая автоповторы;
`hv on` принимает запрос работы, сразу пытается включить HV и при необходимости
продолжает попытки в фоне. Успех команды `on` означает принятие запроса;
текущее состояние показывает статус. Поле `Request: ON/OFF` отображает запрос.
Отдельная команда `hv reset` и API сброса fault удалены. Повторный `on`
при работающем регуляторе не сбрасывает интегратор.
Ошибки инициализации/ADC, отсутствие свежего отсчёта, активный флаг AWD
или напряжение на пороге OVP и выше по-прежнему запрещают включение.
Ошибки инициализации/ADC и аварийный shutdown автоматически не перезапускаются.
Защита OVP, лимит duty и запрет управления без свежего ADC сохранены.

В контуре 1 кГц нет вызова `bsp_hv_get_status()` с копированием всей
телеметрии и маскировкой IRQ: BSP передаёт код fault и признак `valid` с отсчётом.
Фоновый `bsp_hv_process()` возвращает код fault после проверки таймаута ADC;
повторный снимок статуса в каждом проходе основного цикла также удалён.
Полный статус читается только для инициализации, включения и диагностики.
При проверке таймаута сначала читается время отсчёта, затем текущее время;
при поступлении нового отсчёта между чтениями устаревшая проверка отбрасывается.
Это устраняет возможность ложного таймаута из-за обновления timestamp в ADC IRQ.

OVP подтверждается тремя подряд полученными EOC с ADC на пороге или выше.
При 2 кГц от первого до третьего отсчёта номинально проходит 1 мс. Уже первый
высокий отсчёт или IRQ AWD немедленно сбрасывает MOE: подкачка прекращается,
но CCR1, запрос включения и интегратор PI сохраняются. Временная пауза
не сбрасывает счётчик TIM17 и не меняет фазу ШИМ относительно ADC.

При чистом EOC ниже порога счётчик подтверждения обнуляется, выход разрешается
с прежним Duty, управление продолжается без полного перезапуска. AWD без EOC
останавливает PWM, но не засчитывается как дополнительный высокий отсчёт.
AWD с более новым безопасным DR также требует следующего чистого EOC;
пока флаг AWD снова активен, выход не разрешается. Третий высокий отсчёт
фиксирует `OVERVOLTAGE`, обнуляет Duty и запускает обычный путь автоповтора.

Во время паузы таймаут свежести ADC остаётся активным. `off`, shutdown
или подтверждённый fault отменяют паузу и запрещают возобновление из ADC IRQ.
Ручное `on` уже включённого HV также не обходит временную блокировку MOE.
В статусе Duty временно равен нулю, пока фактический выход запрещён.

Сырые Out/ADC и число отсчётов обновляются всегда. Высокие отсчёты, отсчёты
с AWD и отсчёты во время паузы передаются приложению с `valid=false`:
они не меняют ни фильтр, ни PI. После нормализации фильтр обновляется вновь,
в том числе при уже зафиксированном fault. Коэффициенты рассчитаны для
штатного темпа 1 кГц; во время пропуска отсчётов интегратор заморожен.
Это подтверждение OVP не распознаёт заниженные помехи ниже порога.

Кольцевая история ADC/CCR1, снимки ISR/TR, Range и диагностические счётчики
удалены. CLI оставляет текущие напряжения, Duty, ADC/rate, состояние,
fault и запрос работы. Новых файлов и библиотек нет.

Коэффициенты PI не настроены по измеренной динамике платы. Требуются проверка
запуска без нагрузки, зажигания лампы, скачков нагрузки 0,5..10 мА и смены уставки;
отсутствие выбросов и колебаний пока не подтверждено. Ограничения тока в схеме нет.

TIM17 сначала получает CCR1=0, HIGH idle, OSSI=1, MOE=0 и AOE=0;
только после этого подключается PA7 AF5. BSP калибрует ADC при ADEN=0,
настраивает analog watchdog, дожидается ADRDY, разрешает ADC IRQ и внешний
триггер, затем запускает TIM3. Учтено ограничение ES0202 на установку ADEN
сразу после калибровки. Таймаут калибровки/готовности — 100 мс; при ошибке
выход остаётся запрещённым, init возвращает false, основной цикл продолжается.

В ADC_CFGR2 проверяется только поле CKMODE. При чтении регистров платы через
SWD получено CFGR2=0x00001000 при CKMODE=0: сравнение всего регистра с нулём
ошибочно отклоняло init из-за зарезервированного бита. Эта проверка исправлена;
масштаб преобразования ADC и условия включения HV сохранены.

TIM17 считает при MOE=0. MOE разрешается при запуске HV после получения
свежего допустимого отсчёта и сброса восстанавливаемого fault. При отключении
сначала сбрасывается MOE, затем CCR1 и его preload. AWD обрабатывается до
вызова регулятора. Сохранён overwrite-on-overrun: используется последний
отсчёт, сам OVR не считается отдельным fault, как и в исходной HAL-конфигурации.
Callback измерения остаётся в контексте ADC IRQ.

Error_Handler, HardFault и NMI вызывают shutdown HV перед остановкой;
shutdown не требует tick и допускает вызов до инициализации TIM17.
Контроль отсутствия ADC в течение 10 мс по-прежнему выполняется из foreground.
Программное отключение не является аппаратной защитой от зависания CPU,
ошибок тактирования, задержек IRQ или превышения тока силовой части.
HV находится в разработке, аппаратная проверка не выполнена.

## RTC и тактирование

Clock init сохраняет HSI/PLL, отдельный HSI14 и LSE. Ошибки запуска генераторов,
PLL и синхронизации RTC имеют таймаут и приводят к Error_Handler; работа
без LSE не добавлялась. Обычный reset сохраняет backup domain и календарь;
смена источника RTC требует сброса backup domain.

Дата/время записываются за один INIT-сеанс; magic CLK1 в BKP0R выставляется
после синхронизации. При ошибке обновления календарь остаётся невалидным.
Сохранены обходы ES0202 для повторного INIT и согласованного чтения shadow
регистров SSR/TR/DR. RTC API вызывается последовательно из foreground
с работающим SysTick. Все программные таймауты требуют обслуживания SysTick.

Светодиод PC13 подключён к +3,3 В и активен при LOW. Разделители часов следуют
тому же уровню через EXTI13 по обоим фронтам (вектор EXTI4_15, priority 3).
Обработчик читает только GPIO IDR; shadow-регистры RTC, Alarm и дополнительный
генератор мигания не используются. Свечение непрерывное всю активную фазу,
без ШИМ, слота TIM1 и ожидания границы кадра. Задержка фронта определяется IRQ,
а не периодом сканирования; длительное запрещение IRQ задерживает переключение.

BSP отдельно владеет A2 и CATHODE_3/7/10/13. Операции BSRR сканера исключают
эти биты и при переключении/пропуске слотов сохраняют разделители. Привязка
статических выходов находится в `bsp_pins.h`. `bsp_nixie_validate_board()`
отклоняет профили, использующие любой зарезервированный электрод, даже погашенный;
`bsp_nixie_present()` дополнительно проверяет готовый план перед копированием.

`bsp_nixie_set_separators()` задаёт независимое разрешение валидного календаря,
`bsp_nixie_set_enabled()` — общее разрешение HV для обоих видов индикации.
При разрешении выходов сразу учитывается текущий уровень PC13. Общая остановка
и защёлкиваемый shutdown синхронно гасят все аноды и катоды; EXTI не может
повторно зажечь точки без разрешений. Два буфера TIM1 содержат только цифровые
слоты, без прежних копий для двух фаз RTC (на 192 байта меньше на 32-битном MCU).

## Статус и последующая проверка

Выполнен просмотр исходников и diff, поиск оставшихся HAL/LL-зависимостей,
сверка имён регистров с локальным CMSIS Device header STM32F051x8.
Агент не запускал сборки, тесты или прошивку. При диагностике HV выполнено
чтение регистров через SWD без halt/reset; найден ложный отказ проверки CFGR2.
Работоспособность исправления требует новой сборки и проверки пользователем.
Размеры Flash/RAM, задержки IRQ и временные параметры после перехода не измерены.

После отдельного разрешения нужны сборка, затем cold boot/reset, сохранение
RTC, длинный TX и непрерывный RX с восстановлением после ошибок, I2C/BME280,
кнопки/buzzer, WS2812 с анализатором и проверка PA7/ADC/HV при запуске,
отключении и авариях. Особое внимание — совместной нагрузке DMA и ADC IRQ.
